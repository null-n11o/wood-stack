# 開発準備の検証記録

これは設計時の履歴。[今回の実装検証](implementation-verification.md)とは別の記録。

対象: 2026-09-22作成の詳細設計・実装計画と管理文書。アプリは未実装。ビルド・アプリの単体テスト・E2Eは今回実行していない。

## 検証項目

- 文書内のローカルMarkdownリンク、JSON構文、CLAUDE.mdの1行形式。
- 上位PLANコピーと正本のバイト一致、索引のSHA-256一致。
- Notionの作業キーと参照URLが1件にまとまっていること。
- 実商品Tの3条件を寸法の両端で再計算。
- 900条件で、ceil算式と長さを順次足す独立した算術検算を照合。購入枚数が必要枚数以上、購入刻みを1段減らすと不足、壁幅を増やして購入量が減らないことを確認。
- specのA01〜A14と実装Taskの対応、広告データと順位処理の分離、送料不明と0円の区別。
- `git diff --check` と `git diff --cached --check`。

算術検算は設計式の検証であり、今後のTypeScript実装が通過したテストではない。実装計画のテストコードはレビュー用の記述であり、実行結果とは区別する。

## 検証結果

2026-09-22に全項目を実行。ローカルMarkdown参照32件、JSON構文、PLANコピー・ハッシュ、CLAUDE形式、Task対応は一致した。算術検算900条件と実商品3例の上下限は全件一致。A01〜A14の受入表とTask 1〜8の存在・対応を確認した。文書の未記入マーカーは検出されなかった。

検証用Pythonは一時ファイル `/tmp/wood-stack-verify-docs.py` で実行した。プロダクトコードや恒久テストとして追加していない。文書差分の空白検査も通過した。

## 自己点検で修正した内容

- 検索の単位予算budgetと壁計算の全量予算mbudgetを分離。
- 寸法の注文可能範囲selectableと納品公差boundedを分離。
- 壁材費用の同点順をofferIdへ固定し、広告情報を参照しないことを明文化。
- 価格・仕様・販売状態の確認日の参照先を定義。
- 検索結果に残るCreemaの展示作品を通常購入候補から除外。
- 初期セットアップ時の「設計へ進まない」案内を現在のレビュー待ちへ更新。

## 未検証と残る制約

実商品は数件の確認であり、市場全体の網羅調査ではない。BASEは今回429で再取得できず、WOODPROには購入単位や注文条件の確認が残る。複数購入先での通常概算を公開時に成立させるためのデータ確認は実装計画に含めた。

画像許可・広告掲載条件・公開先の確認や、実際の購入・施工適合の検証は行っていない。詳細は[レビュー案内](review.md)に記載。
