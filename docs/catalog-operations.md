# 商品・記事の更新手順

## 登録と出典

台帳は `src/data/catalog.json`、記事は `src/content/articles/`。設計用の `docs/research/catalog-example.json` は取込元にしない。販売店・商品・寸法バリエーション・販売条件・広告を別IDで管理する。IDはURLと比較選択に使うため再利用しない。

商品ページと注文画面を読んで確認し、URL・JSTの確認日・確認方法・対象フィールドをevidenceへ記録する。カート投入や注文は確認手段にしない。商品固有の説明は自作文とし、出典の長文転載を避ける。直接取得できなかった情報の確認日を更新しない。

- 寸法の注文可能範囲はselectable、納品公差はbounded。幅と有効幅も区別する。注文寸法を特定できない商品を通常概算へ入れない。
- ケース入数、最低注文数、注文刻み、上限を確認する。セット価格を枚単価として登録しない。
- 税込固定価格、参考価格、見積もり、未確認を区別する。送料未確認はunknownとし、0円は確認済みfreeだけに使う。
- 送料の `regions: ["all"]` は全国共通条件を直接確認できた場合だけ使う。地域条件や個別見積もりが残れば送料込み小計を出さない。
- 登録候補はdraftに置く。公開状態へ進める前に用途、寸法、価格、購入単位と通常購入先の根拠を確認する。

## 取込と復旧

取込は完全なJSON構造の各配列をIDでupsertする。入力にない既存IDは保持するため、削除操作には使わない。10MiBを超える入力は拒否する。

```sh
# 差分と現在台帳のshaを取得。書込なし
npm run import:catalog -- --input /path/to/confirmed-catalog.json
# 出力されたshaと追加・更新対象を確認して適用
npm run import:catalog -- --input /path/to/confirmed-catalog.json --apply --expected-sha <sha>
npm run verify
git diff -- src/data/catalog.json
```

適用前に参照関係を含め全件検証し、SHA一致と排他lockを確認する。一時ファイルを作成してrename後に保存内容を再確認する。検証失敗やSHA不一致では台帳を変更しない。lockが残った場合は実行中プロセスの有無を確認し、自分の中断処理が残したlockだけを除く。他の更新を強制上書きしない。

保存後の確認が失敗した場合は実ファイルとGit差分を調べる。同じ取込を直ちに再実行しない。誤登録は前の確認済み値への修正コミットで戻す。削除よりdraft化や販売終了状態を優先し、比較URLでの既存ID参照も検証する。

## 再確認と停止

価格・送料・販売状態は30日、仕様は90日を超えると通常概算や価格順位から外れる。期限はJST日付で判定する。ブラウザ計算と検索は閲覧日の値を使う。静的ページはビルド時点の表示なので、定期再確認後に再ビルドする。公開後の配信更新は別途承認された運用で行う。

リンク切れ・販売終了・誤記の報告を受けたら根拠を再確認し、販売状態と確認日を更新する。確認できない値はunknownへ戻す。価格が変わった場合は新しい価格出典を記録し、旧日付だけを更新しない。

画像は取得元、利用根拠、確認日、期限、必要なクレジットが揃ったpermittedだけを表示する。許諾を確認できなければ画像を登録しない。運営メモや証跡原本をpublicへ置かない。許諾失効時は画像レコードと参照を止め、public内の画像実体も除去して生成物を確認する。

広告は承認済み・期限内・許可host一致だけを使用する。通常リンクを常に保持し、広告停止や期限切れでは通常リンクへ戻る。広告レコードの変更で検索・計算・関連記事の順位を変えない。広告リンクにはsponsored/nofollowを付ける。

## 記事と受入

記事frontmatterにcategory、対象productIds、検索preset、出典、更新日を記録する。draft商品への参照、未来日、未知の絞り込み条件は `npm run check:content` で検出する。公開記事は100件まで。

通常ビルドは実台帳だけを使用する。試験データは `npm run build:test` が `dist-test` へ出力し、通常の `dist` へ混ぜない。公開上限は500販売条件・非圧縮JSON 1MiB。`npm run verify` で生成リンクと画像参照も確認する。

更新差分を短命ブランチで検証・コミット・pushし、PRで確認する。マージ・公開は別途明示承認の対象。公開前には2購入先以上の通常概算可能な板材、広告条件、配信先、訂正受付先を確認する。現時点の不足は[直接確認記録](research/2026-09-22-registration.md)を参照。
